# CodeGenome

A comprehensive binary analysis and comparison tool that combines static and dynamic analysis techniques to extract meaningful metrics from executable files and visualize similarities between multiple binaries.

## Overview

CodeGenome is designed to help researchers, reverse engineers, and security professionals analyze binary executables by:

1. Extracting code structure metrics via static analysis
2. Monitoring runtime behavior via dynamic analysis
3. Quantifying similarities between multiple binaries
4. Visualizing analysis results with radar charts
5. Detecting syscall patterns and behavioral similarities

This tool is particularly useful for:
- Malware analysis and variant detection
- Comparing compiler optimizations
- Identifying code reuse across binaries
- Analyzing obfuscated binaries
- Evaluating code generated by different systems (e.g., AI-generated code)

## Features

### Static Analysis Capabilities
- Function count and structure analysis
- Instruction mix categorization
- Control flow complexity measurement
- Memory access patterns detection
- Heap operations tracking
- Import and syscall identification

### Dynamic Analysis Capabilities
- Syscall monitoring and frequency analysis
- Syscall sequence recording and pattern matching
- Runtime behavior characterization
- N-gram similarity calculation for behavior comparison

### Similarity Analysis
- Radar chart visualization of multiple metrics
- Euclidean and cosine distance calculations
- Normalized and raw metrics comparison
- CSV export of distance matrices

## Requirements

### Required Software
- Python 3.6 or newer
- Radare2 (r2pipe)
- strace (for dynamic analysis)
- matplotlib
- numpy
- scikit-learn

### Installation

#### Method 1: Using Virtual Environment (Recommended)

1. Clone the repository and navigate to it:
   ```bash
   git clone <repository-url>
   cd CodeGenome
   ```

2. Create and activate a Python virtual environment:
   ```bash
   python3 -m venv venv
   source venv/bin/activate  # On Windows: venv\Scripts\activate
   ```

3. Install Python dependencies:
   ```bash
   pip install -r requirements.txt
   ```

4. Install system dependencies:
   ```bash
   # Debian/Ubuntu
   sudo apt install radare2 strace
   
   # Fedora/RHEL
   sudo dnf install radare2 strace
   
   # Arch Linux
   sudo pacman -S radare2 strace
   ```

5. (Optional) For building sample binaries with advanced features:
   ```bash
   # Debian/Ubuntu
   sudo apt install libmicrohttpd-dev libcurl4-openssl-dev
   ```

#### Method 2: System-wide Installation

1. Install Python dependencies:
   ```bash
   pip install r2pipe matplotlib numpy scikit-learn
   ```

2. Install system dependencies:
   ```bash
   # Debian/Ubuntu
   sudo apt install radare2 strace
   
   # Fedora/RHEL
   sudo dnf install radare2 strace
   
   # Arch Linux
   sudo pacman -S radare2 strace
   ```

## Usage

### Quick Start

After installation, you can quickly test the tool with a simple example:

```bash
# Activate virtual environment (if using Method 1)
source venv/bin/activate

# Create simple test programs
echo '#include <stdio.h>
int main() { printf("Hello World!\\n"); return 0; }' > test1.c
echo '#include <stdio.h>
int main() { printf("Hello CodeGenome!\\n"); return 0; }' > test2.c

# Compile them
gcc -o test1 test1.c
gcc -o test2 test2.c -O2

# Analyze with CodeGenome
python3 codegenome.py test1 test2
```

This will generate:
- Console output with detailed analysis
- `radar_comparison.png` - Visual comparison chart
- `distance_matrix.csv` - Similarity metrics

### Basic Usage

```bash
python3 codegenome.py base_bin variant1 variant2 [variant3...]
```

The first binary is considered the "base" or reference binary. All other binaries will be compared against it.

### With Dynamic Analysis

To include dynamic analysis with syscall tracing:

```bash
python3 codegenome.py -strace base_bin variant1 variant2 [variant3...]
```

The `-strace` flag (or `-insecure` for backward compatibility) enables runtime analysis using strace, which provides more accurate syscall information but requires the binaries to be executable on the current system.

### Example

```bash
# Compare three calculator implementations
python3 codegenome.py -strace calculator calculator_v2 calculator_beta
```

## Understanding the Output

The tool generates several types of output:

### 1. Per-Binary Metrics

For each analyzed binary, the tool displays:
- General metrics (function count, instruction count, complexity)
- Instruction distribution (percentage of different instruction types)
- Memory operations (heap allocations, etc.)
- Syscall usage statistics

### 2. Visual Output

- `radar_comparison.png`: A radar chart showing the normalized metrics of all binaries for easy visual comparison

### 3. Similarity Matrices

Three distance matrices showing similarity between binaries:
- Raw Euclidean distance (absolute differences)
- Normalized Euclidean distance (scale-independent)
- Cosine distance (angle-based similarity)

Lower values indicate greater similarity between binaries.

### 4. Syscall Analysis (with -strace)

- Most frequent syscalls per binary
- Syscall sequence patterns
- N-gram similarity analysis (for n=2, 3, and 4)

### 5. CSV Output

- `distance_matrix.csv`: Contains all three distance matrices for further analysis

## Analysis Dimensions

The tool analyzes binaries across these key dimensions:

1. **Code Size**: Total instruction count
2. **Control Flow**: Percentage of control flow operations (jumps, calls, etc.)
3. **Data Movement**: Percentage of data transfer operations
4. **Computational**: Percentage of arithmetic/logical operations
5. **Memory Access**: Percentage of memory-accessing operations
6. **Function Diversity**: Number of functions
7. **Complexity**: Cyclomatic complexity metric
8. **Total Syscalls**: Number of system call invocations

## Advanced Usage

### Analyzing Non-Executable Files

For binaries that can't be executed (e.g., from different architectures or malware):

```bash
python3 codegenome.py base_bin variant1 variant2
```

Without the `-strace` flag, the tool uses only static analysis.

### Batch Analysis

For analyzing many binaries at once:

```bash
python3 codegenome.py -strace reference_bin $(find samples/ -type f -executable)
```

## Evaluating Code Generation & Polymorphism

### LLM Code Mutation vs MetaME Polymorphic Engine

This tool is particularly valuable for comparing and evaluating different approaches to code mutation and generation:

#### Analyzing AI-Generated Code Variants

The tool can assess how different Large Language Models (LLMs) approach code generation and mutation:

1. **Implementation Diversity**: Measure how differently each LLM implements the same functionality by comparing:
   - Instruction mix distributions
   - Control flow complexity
   - Memory access patterns
   - Syscall preferences

2. **Analysis Workflow**:
   ```bash
   # Generate equivalent programs with different LLMs
   # Example: calculators implemented by different AI systems
   python3 codegenome.py -strace original_calc gpt_calc claude_calc gemini_calc
   ```

3. **Interpretation**:
   - Higher distance metrics between LLM variants suggest more diverse implementation strategies
   - Similar syscall sequences despite different static metrics indicate functional equivalence
   - Analyze which LLMs produce more efficient code (fewer instructions, better memory usage)

#### Comparing with MetaME Polymorphic Engine

[MetaME](https://github.com/a0rtega/metame) is a known polymorphic engine that transforms binaries while preserving functionality. This tool allows you to:

1. **Detect Polymorphic Transformations**:
   - Compare original binary with MetaME variants
   - Observe how static metrics change while dynamic behavior remains similar
   
2. **Analysis Workflow**:
   ```bash
   # First create variants with MetaME
   metame original_binary -o metamorphed_variant

   # Then analyze with this tool
   python3 codegenome.py -strace original_binary metamorphed_variant llm_variant
   ```

3. **Key Insights**:
   - MetaME typically shows high static differences but nearly identical syscall patterns
   - LLM mutations often show more diversity in both static and dynamic behavior
   - Compare n-gram syscall similarity to identify functionally equivalent code despite structural differences

4. **Research Applications**:
   - Evaluate LLMs' ability to produce functionally equivalent but structurally diverse code
   - Assess which approach creates more resilient code variants
   - Study detection evasion capabilities of different code transformation techniques

This analysis can provide valuable insights for security research, compiler optimization, code diversity studies, and AI code generation benchmarking.

## Troubleshooting

### Permission Issues

Ensure binaries have execution permissions for dynamic analysis:

```bash
chmod +x binary_name
```

### Binary Format Issues

If Radare2 has trouble analyzing a file:

1. Ensure it's a valid executable format
2. Try running `file binary_name` to verify the format
3. For stripped binaries, results may be less detailed

### Long Analysis Times

For large binaries:

1. Start with static analysis only (omit `-strace`)
2. Consider analyzing just a subset of variants at once
